# MidoriVPN browser extension 2.0.0

Firefox and Chromium extension that routes browser traffic through an authenticated HTTPS CONNECT gateway. It is a browser proxy client, not a device-wide WireGuard client.

## Security properties

- OAuth 2.0 Authorization Code + PKCE with strict callback origin, path and state validation.
- Access/refresh tokens encrypted with AES-GCM using a non-extractable key stored by IndexedDB; no password-derived or cleartext persistence fallback.
- Production CSP denies every source by default and permits only configured API/identity origins.
- Proxy routing is available only when the selected server advertises an enabled, healthy normalized `proxy` transport.
- There is no implicit host, scheme or port fallback.
- Proxy authentication uses a short-lived `vpn-proxy` token; a general OAuth access token is never sent to the proxy.
- Missing credentials/permissions/configuration fail closed through a loopback black-hole proxy instead of leaking traffic directly while the VPN toggle is on.

## Rootless development

Create the local `.env` from `.env.example`; never commit client IDs, callback origins or API endpoints that belong only to a deployment.

```bash
bash ../scripts/pod.sh npm ci
bash ../scripts/pod.sh npm run check
bash ../scripts/pod.sh npm audit --audit-level=high
```

The check runs strict type checking, lint with zero warnings, unit tests and both production bundles.

Build one browser explicitly:

```bash
bash ../scripts/pod.sh npm run build:firefox
bash ../scripts/pod.sh npm run build:chrome
```

ZIP artifacts are generated by the production Webpack configuration. Load only the matching browser output when testing; Firefox and Chromium manifests have different proxy/auth capabilities.

## Runtime flow

1. The background worker restores the encrypted OAuth session.
2. `/api/v1/control/servers` is filtered to servers with a healthy `proxy` transport.
3. The user selects a server and enables browser proxy mode.
4. `/api/v1/control/proxy-credentials` returns a scoped token and verified proxy endpoints.
5. Browser proxy APIs receive the normalized TLS host/port and authenticate CONNECT requests.
6. A `407` triggers a throttled scoped-token refresh; definitive auth failure disables the user-visible session.
